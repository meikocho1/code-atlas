# 10万円を超える経費に、上長の承認が必要になります

**結論:** 経費を申請する人は、10万円を**超える**申請が上長の承認待ちになります。10万円ちょうど以下は、これまでどおりすぐ承認されます。却下や、承認者が上長かどうかの確認はまだありません。

**対象:** `Baseline expense submission (always auto-approved)` コミットから現在の作業ツリーまで（未コミット）。変更の理由を書いたコミットメッセージや PR 説明はありません。

```atlas-stats 変更の概要
変更ファイル: 1 | 追加 0・変更 1・削除 0
追加行: +11
削除行: −0
```

## 誰に影響するか（BUSINESS）

```atlas-impact 影響範囲
申請者 / 経費の申請: 変更 | 10万円を超えると、すぐには承認されず上長の承認待ちになる
上長 / 経費の承認: 追加 | 承認待ちの経費を承認できる
上長 / 経費の却下・差し戻し: 未確認 | この変更には却下する手段がない
上長 / 承認依頼の通知: 未確認 | 承認待ちになったことを知らせる処理はこのコードにない
経理 / 支払い・集計: 未確認 | 「承認待ち」の経費をどう扱うかは、このリポジトリの外
```

## 業務の流れ（BUSINESS）

```atlas-flow 経費申請の流れ
申請者: 経費を申請する
[変更] 10万円を超える => 上長の承認待ちになる
10万円以下 => その場で承認される
[追加] 上長: 承認待ちの経費を承認する
```

承認待ちの経費を承認すると「承認済み」になります。承認待ち以外の経費を承認しようとするとエラーになります（`expenses.py:20-23`）。

## ルールを具体例で（BUSINESS）

| 申請額 | 結果 | 根拠 |
| --- | --- | --- |
| 99,999円 | その場で承認 | `expenses.py:14-17` |
| 100,000円 | その場で承認（上長の確認なし） | `expenses.py:14-17` |
| 100,001円 | 上長の承認待ち | `expenses.py:14-15` |

> [!IMPORTANT]
> 境目は「10万円**を超える**」です。10万円ちょうどは承認なしで通ります。

## 開発者向けの根拠（CODE）

- しきい値は `APPROVAL_THRESHOLD = 100_000`（`expenses.py:3`）。判定は `expense.amount > APPROVAL_THRESHOLD`（`expenses.py:14`）。
- 承認は `approve_expense()` で、状態が `awaiting_manager_approval` のときだけ `approved` にします。承認者を受け取る引数はありません（`expenses.py:20-23`）。
