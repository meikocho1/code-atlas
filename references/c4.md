# C4-style component view

Use a context, container, or component view when the change alters **who depends on whom**. Choose one level and keep all boxes at that level. Verify each component in source or deployment configuration and each edge through a call, event, dependency, or data access. Label boundary crossings with the observed interface or protocol.

Do not draw a whole-system map to explain one changed function. Group or omit unrelated pieces. If there is no actual cross-component change, use prose or another view. “C4-style” here names the abstraction discipline; strict C4 notation is not required.
